# InputBridge Mobile — PySide6 source

This is the PySide6 companion-client source. The previous Kivy implementation is retained separately under `mobile_kivy_legacy/`.

## Important: source-only workflow

This repository's CI **does not build, publish, or attach an APK/AAB**. It only performs Python compilation and automated unit tests. The goal of this workflow is to validate the source without spending time on Android cross-compilation.

A raw `.py` file cannot run as a native PySide6 app directly on Android. Android does not ship a Python interpreter or the Qt/PySide runtime with which this source could start. Qt's official deployment documentation explains that these components must be packaged for Android: [PySide6 Android deployment](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-android-deploy.html). No APK is generated by this repository's current CI.

## Run and test the source on a desktop

Use Python 3.11 and install the listed dependencies:

```bash
python -m pip install -r requirements.txt
python -m compileall -q main.py test_mobile_client.py
python -m unittest -v
python main.py
```

This launches the same Qt Widgets interface for development on a desktop with a supported Qt runtime. Camera and sensor functionality depend on the desktop device and the installed Qt modules.

## Included screens and features

- Secure connection with TLS certificate pinning, retries, saved PC endpoint, and persistent phone identity.
- On-screen gamepad with face buttons, bumpers, menu/system buttons, D-pad, dual analogue sticks, analogue L2/R2 triggers, Standard/Driving modes, and optional accelerometer steering with centre calibration.
- Mouse trackpad with relative cursor movement, tap-to-click, left/right/middle buttons, one-finger movement, two-finger scrolling, and sensitivity settings.
- Remote PC text entry, special keys, modifiers, allowlisted keyboard shortcuts, media keys, explicit clipboard read/write, approved app launch shortcuts, presentation controls, PC status, and confirmation-gated power actions.
- Phone-side controls are enabled only when the desktop server reports that the corresponding permission is allowed. Power actions remain gated by the desktop setting and phone confirmation.
- Camera QR scan with runtime permission handling and a manual JSON/clipboard fallback when the camera or QR decoder is unavailable.
- Responsive dark Qt Widgets interface designed for touch use.

## Security and compatibility

- The desktop server and mobile client must both be updated to the current TLS protocol.
- The QR supplies the server address and public SHA-256 certificate fingerprint. It never exports the private TLS key.
- Remote actions require explicit permission on the Windows desktop. Only approved app shortcuts and keyboard shortcuts are accepted by the server.
- Controller state is reset to neutral on disconnect to prevent held buttons or triggers from persisting into a later session.
- Camera and motion-sensor availability depends on the device, installed Qt modules, and runtime permissions.

## Pair with the Windows desktop app

1. Start InputBridge on Windows and open **Server**.
2. Start the server and choose **Show Phone Pairing QR**.
3. In the client, use **Connect → Scan pairing QR**. If scanning is unavailable, paste the full QR JSON or enter the PC address, port, and SHA-256 fingerprint.
4. Keep both devices on the same local network. The client checks the live TLS certificate fingerprint before sending controller state.
5. Enter the per-device pairing code on first connection. Use the **Gamepad**, **Mouse**, or **Remote** screens as allowed by the desktop permissions.
